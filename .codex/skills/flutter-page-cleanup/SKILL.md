# Flutter Page Cleanup

本 skill 仅用于当前仓库。

这是当前仓库的强制技能，不是可选参考。

强制规则：

- 只要用户表达包含“整理页面代码”“重构页面结构”“优化页面实现”“收拾这个页面”“按之前那个标准整理”“整理某某页/弹窗/面板代码”等意图，必须先执行本 skill，再开始改代码。
- 命中本 skill 后，不允许直接做零散样式修改；必须先从结构、适配、组件职责、数据来源、交互时机几个方面完成一次整理。
- 如果用户没有明确要求改视觉稿，则默认目标是：不改变设计意图，只提升结构清晰度、自适应能力、可维护性与稳定性。
- 页面整理完成后，必须执行相关格式化；Flutter 页面代码改动后，必须至少执行一次 `fvm flutter analyze`。

适用场景：

- 用户说“整理这个页面代码”
- 用户说“重构这个页面/弹窗/面板”
- 用户说“代码可读性太差，拆一下”
- 用户说“按之前整理结束页的标准处理”
- 用户说“这个页面固定高度太多，改成自适应”
- 用户说“某个页面容易 overflow，顺手把结构整理一下”
- 用户说“统一底部按钮/区块/卡片/分割线写法”

## 核心目标

页面整理默认同时追求四件事：

1. **结构清晰**：页面文件只保留页面编排，复杂区块拆成小组件
2. **布局稳健**：尽量减少大块固定高度，优先自然撑开与滚动兜底
3. **职责合理**：UI、流程、数据来源、交互时机分开，不把多类职责揉在一起
4. **视觉不跑偏**：不擅自改变设计意图，只修结构与实现方式

## 工作流程

1. 先做 code review，再动手。

至少检查：

- 是否存在大块固定高度容器
- 是否存在 `RenderFlex overflow` 风险
- 是否存在页面文件过长、多个区块混在一起
- 是否存在按钮、卡片、分隔线、统计区等重复结构
- 是否存在数据来源不合理、弹窗打开时机不稳、先打开后拿数据的问题
- 是否存在 `Container + InkWell` 但缺少 `Material` 的情况

2. 判断哪些尺寸可以固定，哪些必须自适应。

默认允许固定：

- 底部按钮高度
- 图标尺寸
- 顶部把手尺寸
- 描边宽度
- 阴影参数
- 圆角
- 进度条细线高度

默认不要固定：

- 大块内容容器高度
- 承载多行文案的卡片高度
- 头部说明区整体高度
- 统计区依赖内容的分隔线高度
- 弹窗整体高度
- 会随着数据、字体缩放、设备宽度变化而明显波动的区块高度

3. 先修结构，再修样式细节。

推荐顺序：

- 先把页面拆成 2 到 5 个职责清晰的小组件
- 再把重复按钮/分隔线/卡片抽成局部私有组件
- 再处理自适应布局与滚动容器
- 最后才统一按钮规格、字体、边距等视觉常量

4. 优先使用更合适的组件组合。

推荐：

- 交互按钮优先 `Material + InkWell`
- 可滚动底部弹窗优先 `ConstrainedBox + SingleChildScrollView`
- 跟内容等高的分隔线优先 `IntrinsicHeight + VerticalDivider`
- 易超长文本优先 `Expanded`、`Flexible`、`TextOverflow.ellipsis`
- 纯展示分隔块优先小组件封装，不要到处手写同样的 `Container`

谨慎使用：

- 为了省事给整个卡片或整个 section 写死 `height`
- 大量 `Positioned` 叠固定占位只为拼页面
- 页面里直接堆太多匿名 `Container/Row/Column`

5. 检查数据来源和交互时机。

页面整理不只看 UI：

- 结束页、结果页、总结页优先读最终结算数据，而不是瞬时 realtime
- 依赖异步结果的弹窗或页面，优先等状态更新完成后再打开
- 不要让页面首次 build 时处于“数据还没准备好但 UI 已打开”的竞态状态

6. 改完后必须自检。

至少确认：

- 页面文件是否明显变短、职责是否更清楚
- 是否减少了不必要固定高度
- 是否保留了按钮/图标等应固定的视觉规格
- 是否避免了新的溢出风险
- 是否没有无意义改变设计稿视觉

## 处理原则

- 默认做“结构优化”，不是“视觉重设计”
- 除非用户要求，否则不擅自改页面文案
- 优先抽局部私有组件，只有跨文件复用价值明确时才抽公共组件
- 修改前注意搜索调用方，避免页面拆分时破坏外部入口
- 页面整理时，如发现明显状态或交互问题，应顺手修到位，不要只做表面拆文件
- 注释使用中文；尽量不删除现有注释，可改得更准确

## 验收标准

一个页面整理完成，至少应满足：

- 页面主文件主要负责组装与流程串联，不再堆积多个复杂 section
- 大块区块以内容自然撑开为主，不再依赖大量固定高度
- 小屏、文案变长、字体略放大时不容易溢出
- 交互按钮、卡片、统计区等组件选型合理
- 数据来源和打开时机没有明显竞态
- 已执行：

```bash
fvm dart format <相关文件>
fvm flutter analyze <相关文件或相关目录>
```

## 快速自检清单

- 是否把“大块固定高度”改成了内容自适应
- 是否保留了按钮/图标这类合理固定值
- 是否把超长页面拆成小组件
- 是否把重复结构抽成了局部组件
- 是否给文本、统计行、旅程行等易挤压区域留了伸缩空间
- 是否检查了异步状态与弹窗时机
- 是否使用了 `fvm` 前缀命令
